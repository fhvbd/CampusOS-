# 一、拆解原则

按 04_开发路线图 的版本节奏（V0.1 → V1.0）纵向拆解，每个版本内部按「设计 → 数据库 → 后端接口 → 前端页面 → 联调测试」横向拆解，符合项目铁律「先设计后编码」「先测试后发布」。

# 八、任务优先级与项目铁律对照

1. 禁止功能膨胀 → 每个版本任务范围严格对应路线图，不额外增加。
2. 禁止娱乐/社交功能 → WBS 中不包含任何社交、娱乐类任务。
3. 优先高频需求 → 通知、课表、日程排在 AI 之前（V0.2~V0.4 优先于 V0.5）。
4. 先设计后编码 → 每个模块均先完成数据库/接口设计，再进入编码。
5. 先测试后发布 → 每个版本末尾均包含「联调测试」任务节点。
