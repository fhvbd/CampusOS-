# CampusOS MVP 开发计划

版本：V1.0
关联文档：02_PRD需求文档.md / 04_开发路线图.md / 12_开发任务拆解(WBS).md

---

# 一、MVP 目标

依据 02_PRD需求文档「MVP阶段目标」，优先解决大学生高频、刚需场景：

- 课表查看
- 通知聚合
- 作业/待办提醒
- 日程管理

**不纳入 MVP 范围**（第二阶段功能，V0.5 之后）：

- AI学习助手
- 奖学金雷达
- 实习雷达

> 遵循项目铁律：禁止功能膨胀、禁止偏离校园场景、优先解决高频需求。

---

# 二、MVP 范围对照路线图版本

MVP = V0.1（基础框架） + V0.2（通知中心） + V0.3（课表中心） + V0.4（日程中心）

AI学习助手（V0.5）及以后版本不属于 MVP，作为 MVP 上线后的下一阶段规划。

---

# 三、MVP 功能清单

| 模块 | 功能 |
| --- | --- |
| 用户 | 登录、个人资料 |
| 首页 | 今日课程、待办事项、最新通知（不含 AI建议卡片） |
| 通知中心 | 通知聚合展示、搜索、收藏、已读管理 |
| 课表中心 | 课表展示、课程详情、考试提醒、教室信息 |
| 日程中心 | 待办事项、提醒、日历视图 |

# 四、阶段划分与验收标准

## 阶段一：基础框架（对应 V0.1）

**目标**：打通登录 → 首页的最小闭环。

**验收标准**：
- 用户可通过学号+密码登录，获得 Token 并本地保存。
- 登录后进入首页，底部导航栏（五栏）正常展示（AI/我的等入口先占位）。

## 阶段二：通知中心（对应 V0.2）

**验收标准**：
- 通知列表可按分类（教务/学院/竞赛等）筛选。
- 通知详情可查看、收藏、标记已读。
- 首页「最新通知」板块展示真实数据。

## 阶段三：课表中心（对应 V0.3）

**验收标准**：
- 用户可查看本周课表，按星期切换。
- 点击课程可查看教师、教室、上课时间等详情。
- 考试提醒可正常触发。
- 首页「今日课程」板块展示真实数据。

## 阶段四：日程中心（对应 V0.4）

**验收标准**：
- 用户可新增、查看、删除待办事项。
- 日历视图可正常切换查看。
- 首页「待办事项」板块展示真实数据。

**四个阶段全部通过验收 = MVP 完成。**

# 五、技术准备（MVP 阶段固定不变）

| 层 | 技术选型 |
| --- | --- |
| 前端 | Flutter（Android / Windows） |
| 后端 | FastAPI（Python） |
| 数据库 | SQLite（开发阶段） |
| 认证 | JWT Token |
| 部署 | 本地运行 |

数据库范围（对应 06_数据库设计书「V1数据库范围」）：仅需 `users`、`courses`、`tasks`、`notices`、`settings`，暂不实现 `ai_records`、`exams`。

# 六、里程碑节奏建议

| 里程碑 | 内容 | 前置条件 |
| --- | --- | --- |
| M1 | 阶段一验收通过（登录+首页闭环） | 项目脚手架搭建完成 |
| M2 | 阶段二验收通过（通知中心可用） | M1 完成 |
| M3 | 阶段三验收通过（课表中心可用） | M2 完成 |
| M4 | 阶段四验收通过（日程中心可用），即 **MVP 上线** | M3 完成 |

各里程碑按 12_开发任务拆解(WBS).md 中对应版本的任务项逐条推进，不设固定日期，以任务完成度为准，避免为赶工期牺牲「先设计后编码、先测试后发布」的项目铁律。

---

# 七、风险与应对

| 风险 | 应对措施 |
| --- | --- |
| 校园通知/教务系统无公开接口，聚合困难 | V0.2 阶段可先支持人工/半自动录入通知源，crawler 逐步迭代 |
| 课表数据来源依赖教务系统格式不统一 | 优先支持手动导入/单一格式适配，不追求一次性兼容所有格式 |
| 需求膨胀（提前做 AI/社交类功能） | 严格对照 PRD「MVP阶段目标」与项目铁律把关，MVP 期间产品决策一律以此为准 |

---

# 八、MVP 之后的过渡

MVP（V0.1~V0.4）验收通过后，按 04_开发路线图 进入 V0.5 AI学习助手阶段，具体任务见 12_开发任务拆解(WBS).md 第六节。MVP 阶段沉淀的用户模块、数据库结构、AI网关目录占位（backend/app/ai/、pages/ai/）将直接复用，无需重新设计。
